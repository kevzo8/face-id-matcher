What is the ID OCR SDK?

A reusable front-end SDK + backend wrapper that accepts one or more identity document images and returns a standardized JSON contract consumed by any application.

Front-End SDK

  • Headless TypeScript library
  • Optional <svi-id-ocr> web component
  • Accepts 1–N images from the app
  • Returns normalized result via backend

Backend Wrapper

  • AWS Rekognition DetectText — raw text + boundaries
  • GROQ (llama-3.3-70b) — normalize to schema
  • Configurable ID type registry
  • Sanitized, standardized responses

Key rule: the SDK never determines front/back of an ID. The consuming app supplies the images, capture sequence, and which sides are required.

Architecture

Front-End SDK

  • extractDocument() — main API
  • listIdentityTypes() — registry
  • <svi-id-ocr> — web component

Backend (FastAPI)

  • POST /id-ocr/ocr/extract
  • GET /id-ocr/identity/types
  • GET /id-ocr/health

The front-end never calls AWS/GROQ directly — all external calls are server-side.

Standardized JSON Contract

Contract is identical for all ID types

  • status — SUCCESS / ERROR
  • id_type_code & id_type_name
  • document_type — canonical key
  • extracted_data — structured fields
  • raw_text_payload — for audit

Missing fields

Returned as null/[]. Never invented.

Configurable Identity Registry

Identity types are not hardcoded — they live in id_config.json and can be added/updated/disabled without code changes.

Registry fields

  • id_type_code — API code
  • id_type_name — display name
  • is_active — enable/disable
  • document_type — output key

Requests for inactive codes are rejected (INVALID_ID_TYPE).

Auto-detection from OCR text when the app doesn't supply a code; app-supplied code always wins.

Security & Isolation

✓ Server-side only

  • AWS credentials & GROQ token live only in backend env
  • Front-end never invokes external AI services
  • No keys exposed to the client

✓ Sanitized errors

  • Responses never leak internal/external details
  • Clear error codes: OCR_FAILED, INVALID_ID_TYPE
  • Diagnostics without implementation details

⚠ Partial extraction supported

If one image fails, the request still returns successfully extracted text + per-image diagnostics.

Front-End SDK Integration

Library API

For React/Vue app code.

Web component

For markup-first / vanilla JS.

Same engine, identical results.

import { extractDocument,
         listIdentityTypes } from 'svi-id-ocr-sdk';

// Optional: fetch active ID types from the registry
const { data } = await listIdentityTypes();

const result = await extractDocument(
  [
    { image: base64Front, label: 'front' },
    { image: base64Back,  label: 'back'  },
  ],
  { endpoint: '/id-ocr/ocr/extract', idTypeCode: 14 },
);

if (result.ok) {
  console.log(result.data.id_type_name);   // "Bataeno Pass"
  console.log(result.data.extracted_data); // standardized + details
} else {
  console.log(result.error.message);       // sanitized error
}

Also available as <svi-id-ocr endpoint="..." id-type-code="14"></svi-id-ocr> with svi-ocr-success/svi-ocr-error events.

Backend API Reference

POST /id-ocr/ocr/extract

// Request
{ "images": [
    { "image": "<base64>", "label": "front" },
    { "image": "<base64>", "label": "back"  } ],
  "id_type_code": 14,       // optional
  "document_type": "..." }  // legacy hint

{ "status": "SUCCESS",
  "id_type_code": 14,
  "id_type_name": "Bataeno Pass",

Running Locally

1. Credentials

cd backend
cp .env.example .env
# add AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY,
# AWS_DEFAULT_REGION, GROQ_API_KEY

2. Backend

cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

Auto-loads backend/.env. Docs at /docs.

3. Demo + SDK

# root: dev server for demo + proxy
cd ocr-sdk
npm install
npm run demo      # -> http://localhost:5173

# frontend build
cd frontend
npm install
npm run build     # -> dist/

4. Test

Open http://localhost:5173/demo/index.html, pick ID images, click Extract.

Tip

Demo has two buttons — Library API and Web component — with loading state. Both hit the same backend.
